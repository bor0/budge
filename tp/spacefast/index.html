Budge-TP is a theorem prover whose checker is about 300 lines of Python and only does string substitution. On this page you can step through it by hand, run the real checker in your browser, and see how Python meta-programs and tactics write the proofs for you while Budge-TP still checks every step.

Four kinds of lines

A Budge-TP file is a list of statements. The first letter of a name says what it is. Names and expressions can be any characters except : and spaces, and # starts a comment.

r…

Rules

Hypotheses, then a conclusion, joined by ->. Lowercase letters are variables you can substitute.

r2 : |- Mx -> |- Mxx
t…

Theorems

Apply a rule (or an earlier theorem), give substitutions x=X;y=Y, then the theorems that satisfy its hypotheses.

thMII : r2 x=tmI! thMI
p…

Prose

Plain text printed as -- text between results. The prefix means prose can never pass for a theorem.

pOnePlusOne : 1 + 1 = 2
<?py ?>

Meta-programs

Python blocks. Whatever they print becomes Budge code and is checked like anything else. They see env and load(path).

<?py load('lib/logic.btp') ?>

What "checking" means

To check t : rule x=X;y=Y h1 h2, Budge-TP replaces every x and y in the rule's hypotheses and conclusion with the values of theorems X and Y, does the same to the given hypotheses, and requires the two lists to be identical strings. If they are, the substituted conclusion becomes the theorem. If not, you get Hypotheses mismatch.

Terms are theorems too

Substitutions point at theorems, not raw text. So a term like II is built first with a rule like rTmMk : xy, and the theorem tmII! holds it. A trailing ! hides a theorem from the output. That's why real proofs have so many tm…! lines.

Tired, wired, inspired


The blog post proves 0 + n = n three ways. Each step up hands more of the writing to Python, and none of it asks you to trust Python.




tired
By hand
Every number needs its own theorem, written line by line. 1 + 1 = 2 alone takes a dozen steps of terms, axioms, and modus ponens.


wired
Python prints the lines
A loop emits the same theorems for you. Budge-TP neither knows nor cares that Python wrote them, but you only get the numbers you asked for (up to tm4!).


inspired
Induction tactics
Ctx, chain, and induction produce one theorem, thZeroAdd : ⊢ALL(EQ(ADD(0,V(0)),V(0))), which is ∀n. 0 + n = n.




Reading the formulas
Numbers are 0, S(0), S(S(0))… Bound variables use de Bruijn indices: V(0) is the variable of the nearest ALL or EX, V(S(0)) the one outside that. So ALL(ALL(EQ(ADD(V(S(0)),V(0)),ADD(V(0),V(S(0)))))) reads ∀m∀n. m + n = n + m. Capital letters like N are parameters: arbitrary but fixed, which is how an induction step talks about "some n".

The tactics, in one place


Tactics live in lib/tactics.py. They are ordinary Python functions that print Budge-TP theorems. Tap a card for more.




Natural deduction, sketched
Transitivity of divisibility (a|b and b|c gives a|c) in lib/divides.btp starts like this:


root = Ctx(reserved={a_, b_, c_})
c1 = root.assume(dvd(a_, b_))   # assume a|b
c2 = c1.assume(dvd(b_, c_))     # assume b|c
# ... unpack both ∃s, rewrite c = b·y = (a·x)·y = a·(x·y), pack again ...
h = root.close(c1.discharge(c2.discharge(...)))


A context is a formula G: ⊤ at the root and (G∧H) after assuming H. A fact X proved there is really the theorem ⊢(G⇒X), so "assumptions" never leave plain Hilbert-style logic.







Why you don't have to trust the tactics


It's the Edinburgh LCF idea: a small trusted checker with a programming language on top. Python can't prove anything by itself. It can only produce candidate steps, and Budge-TP checks each one.

Python blocks, tactics.py, loops, anything clever.A bug here can only produce a step that gets rejected.
